# Cordial 0.14.2 — typing in your own alphabet, and staying signed in

## Text boxes accept every keyboard layout, not just Latin ones

Cordial asked X11 for the character behind each key, and X11's answer is
Latin-1 and nothing else. Every other script — Cyrillic, Greek, Hebrew, Arabic,
Thai — came back empty, so the key did nothing and no Roblox text box ever saw
it. X11 is the default whenever you are not on Wayland, so this was most people
on Xorg typing in their own alphabet.

Cordial now asks libxkbcommon, which already ships with every layout your
system has. Nothing is enumerated and no alphabet is special: the test compares
Cordial's answer against that library across the whole keysym range, so a
script nobody here thought of is covered by the same code as the rest.

Found and fixed by [@BrokenByteOfCode](https://github.com/BrokenByteOfCode) in
[#45](https://github.com/luohoa97/cordial/pull/45).

## Staying signed in

A saved session could read back as its first line only, so Cordial forgot who
you were and sent you back to the login page. The desktop's Secret Service cuts
a stored value at a newline, a tab or an `=`, and a cookie store contains all
three. It is encoded before storing now, and sessions saved by older versions
are still read as they are. Also from [#45](https://github.com/luohoa97/cordial/pull/45).

## Settings → Version can download older builds, not just keep them

Under the builds Cordial keeps, the page now lists the versions APKPure has for
x86-64, with a download button on each. The list is fetched when you open that
page, never at startup, so a slow or unreachable mirror shows a message there
and does not slow anything else down.

A download is checked against Roblox's signature the same way an update is,
and is kept beside the build you are using without replacing it. It then
becomes this profile's build: without that, Cordial would clear it out as the
oldest build on its next launch. "Follow the current build" puts things back.

The same warning as before applies, and more so the further back you go:
**Roblox refuses old clients eventually**, and an old enough build will not join
games at all.

**Only the list has been checked against the real mirror so far, not a full
download through the page.** If a download fails, the message on the page is
what would help.

## Roblox can ask for the microphone

Roblox asks for microphone access inside the game, and nothing in Cordial was
answering, so the ask went nowhere. Cordial now grants it. Contacts access is
still refused on purpose: Roblox uses it to match your address book against
its users.

## Roblox is told the platform your profile claims to be

A profile set to the Windows 11 identity sends a Windows 11 User-Agent and
model, and then answered "Linux" when the engine asked what platform it was.
It now answers what the profile says it is. Nothing user-visible is known to
turn on this; it is here so the identity a profile presents is one thing rather
than two.

## What is still broken

**Voice chat still does not work.** The microphone permission above was a step,
not the fix. With it granted, Roblox now gets as far as building its voice
session and then stops: the session id is empty, no connection is ever opened
and no audio is captured or sent. The server side is not what is refusing —
Roblox's own settings for the account come back saying voice is enabled,
eligible and verified. Why it stops after that is not known.

Earlier notes said this logged nothing and ran through a part of the platform
Cordial had not implemented. Both were wrong: it logs the whole sequence, and
the platform pieces suspected at the time turned out to be answered already.
[#47](https://github.com/luohoa97/cordial/issues/47) has the log, the captured
server response, and the list of explanations already ruled out, so anybody
picking it up does not start over. Sober has voice working; Cordial does not.

**Resizing the window is glitchy for at least one person**, and **the
TaskScheduler crash on a second launch is still being reported.** Neither has
been reproduced here. For either, `cordial --diagnostics` and the full log help
most.

Everything listed as broken in [0.14.1](v0.14.1.md) still is.
