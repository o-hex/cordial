# Cordial 0.15.0 — voice chat, and browser Play picks your account

## Voice chat reaches the network

Pressing the microphone button in a voice-enabled game now gets past the point
it used to stop at. Two things were missing. Roblox's permission answer has to
be delivered twice — published as a protocol response *and* resolved through the
async callback — and microphone capture has to be callback-driven rather than
waiting on blocking reads.

**Be careful how much you read into that, because the verification is partial.**
Audible transmission in a real game was confirmed by the contributor who wrote
the fix, on their own combined build, *before* the stop/restart and cleanup
hardening that followed. The code actually in this release has automated
verification only: native lifecycle, ABI and AddressSanitizer runs. Nobody has
yet confirmed audible speech on exactly these bytes. Only the current default
microphone was tested, on one distribution.

So if voice does not work for you, that gap is the first thing to suspect rather
than the last, and an issue with your log would be worth more than usual.
`CORDIAL_PERMISSIONS_DUAL_RESPONSE=0` restores the previous behaviour if the new
delivery causes trouble.

This closes [#47](https://github.com/luohoa97/cordial/issues/47), which holds
the investigation and the list of explanations that were ruled out along the way.

## Clicking Play in the browser opens the right account

Clicking Play on Roblox's website now checks which account the browser is signed
into and launches that account's saved Cordial profile, without showing the
picker. Opening Cordial from its desktop icon still shows it. No browser
extension is involved.

Sign into each account once in its own profile so its session is saved, and
routing takes it from there. If no saved profile matches, several do, or the
lookup fails, the launcher opens with the link waiting and you choose — it never
guesses. A profile that is already running gets the usual busy-profile dialog.

The ticket the browser hands over is used to ask Roblox which account it is, and
then discarded; it is never written into a profile. `CORDIAL_BROWSER_ACCOUNT_ROUTING=0`
turns the whole thing off. The reasoning is in
[ADR-035](../adr/ADR-035-browser-account-routing.md).

## A title bar you can hide, for tiling window managers

Settings → Appearance → Game window → Title bar now offers **Hidden** alongside
Default and Compact. Hidden removes the bar without requesting fullscreen, so a
tiled window keeps its tile, and leaving fullscreen will not put the bar back.

Two things to know before choosing it. **The window controls go with the bar** —
use your desktop's own shortcuts to move or close the game, and the launcher to
change the setting back. And it applies to **Wayland game windows only**: the
X11 runtime uses an unrelated native window and is unaffected.

## Staying signed in, on a machine with a fussy keyring

Saved sessions are stored through whichever secret backend you have configured.
The default `auto` prefers the desktop Secret Service and falls back to a
`0600` file in the profile when the service is unavailable, and explicit
`keyring` and `file` choices are honoured as given.

## What is still broken

**Voice is not verified end to end on this build.** See the first section — this
is the caveat most likely to affect you.

**Resizing the window is glitchy for at least one person**, and **the
TaskScheduler crash on a second launch is still being reported.** Neither has
been reproduced here. For either, `cordial --diagnostics` and the full log help
most.

When an unrecognised launch link falls back to the manual path, the original URL
is still passed as a command-line argument and stays visible in
`/proc/<pid>/cmdline` to other users on the same machine. Recognised links have
their ticket stripped before launch.

Everything listed as broken in [0.14.2](v0.14.2.md) still is, except voice chat.
