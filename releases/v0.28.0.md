title: "Cordial 0.28.0: PartyDeck, gamescope and controllers"
---
## What you can do now

- **Start a game from another program.**
  `cordial --profile P --play [--place-id N] [--fullscreen] [--set key=value]`
  opens straight into Roblox on that profile, with those settings for that run
  only. Several can run at once, one per profile. `cordial --help` lists the
  exit codes a script can act on. See [PartyDeck](https://cordial.mintlify.app/partydeck).
- **PartyDeck split screen.** Handlers for a native install and for the Flatpak
  are in `packaging/partydeck/`. Each player's game sees only its own
  controller. Tested with a stand-in that starts Cordial the way PartyDeck does,
  not with PartyDeck itself.
- **gamescope works.** Inside gamescope the game used to exit at once with no
  window and no error. It now opens, at full speed.
- **Controllers reach the Flatpak.** It could not see `/dev/input` at all, so
  no pad ever worked there. It now asks for input devices, which needs Flatpak
  1.15.6 or newer; on an older Flatpak the app still runs, without pads, and
  [Controllers](https://cordial.mintlify.app/controllers) says how to grant it.
- **Controllers read correctly.** A pad without every standard axis had its
  right stick read as a trigger and its face buttons read one place out
  ([#113](https://github.com/luohoa97/cordial/issues/113)). Cordial now reads
  the layout the pad declares. Neither change is tested with a real pad yet.
- **Holding a key on X11 no longer restarts hold-to-interact prompts**
  ([#106](https://github.com/luohoa97/cordial/issues/106)).
- **The camera turns on Hyprland when you hold right click**
  ([#56](https://github.com/luohoa97/cordial/issues/56)). The cursor stays free
  while you drag, as it did before 0.26.0; shift lock and first person still
  lock it. `CORDIAL_DRAG_LOCK=1` brings back the old behaviour.
- **Display refresh follows a fast monitor.** On a 120 Hz or faster screen the
  Frame rate limit's **Display refresh** now runs at the monitor's rate instead
  of 60 ([#103](https://github.com/luohoa97/cordial/issues/103)). The list also
  gains 360 and 480 ([#101](https://github.com/luohoa97/cordial/issues/101)).
- **Roblox 2.702.0.622 loads.** It needed a function Cordial did not provide
  ([#110](https://github.com/luohoa97/cordial/issues/110)).
- **Save logs for bug reports.** **Report a Problem → Save logs…** writes one
  `.zip` with Cordial's and Roblox's logs, with your account details removed.
  The issue forms ask for it.
- **The docs site lists every release**, including this one.

## Also

- Two tests no longer fail when your umask is 0077, and Roblox's worker count
  respects a CPU limit set on Cordial. Thanks to hnrie
  ([#102](https://github.com/luohoa97/cordial/pull/102)).

## What is still broken

**The signed-in startup freeze.** Roblox can stop drawing on the loading screen
after sign-in. The launcher restarts a client stuck that way, up to twice.

**You cannot sign in inside gamescope.** The game runs on X11 there, which has
no sign-in window. Sign each profile in from a normal Cordial window first.
PartyDeck's guest profiles are refused.

**Hyprland: the cursor moves while you drag the camera.** That is the cost of
the #56 fix. None of the Hyprland, X11 key-repeat and controller fixes is
confirmed by a reporter yet.

**Movement keys can be dead after joining a game.** Move the mouse while the
place loads and it does not happen. The automatic fix is still untested
([#29](https://github.com/luohoa97/cordial/issues/29)).

**If the launcher process itself is killed, the game goes with it.**

**On the Nintendo Switch, games crash a few seconds in**
([#85](https://github.com/luohoa97/cordial/issues/85)).

The rest of the list in the
[0.24.0 notes](https://github.com/luohoa97/cordial/releases/tag/v0.24.0) still
applies.
